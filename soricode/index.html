코드 구조

테두리바깥 한 줄은 모두 검은 칸입니다. 판독기는 이 사각 테두리로 코드를 찾고 기울기를 바로잡습니다.
눈금테두리 바로 안쪽 줄에서 위쪽과 왼쪽은 검정과 흰색이 번갈아 나오고, 아래쪽과 오른쪽은 흰색입니다. 위쪽 눈금으로 가로 칸 수를, 왼쪽 눈금으로 세로 칸 수를 알아내고 방향도 정합니다.
크기가로와 세로를 각각 24칸부터 176칸까지 4칸 단위로 정합니다. 정사각형이 아니어도 되지만 긴 변은 짧은 변의 4배 이하여야 합니다. 둘레에 흰 여백 4칸 이상이 필요합니다.
점 모양 (선택)안쪽 칸은 네모 대신 지름이 칸의 88%인 둥근 점으로 그려도 됩니다. 바깥 테두리 한 줄은 반드시 이어진 선이어야 합니다. 판독기는 칸 가운데를 읽으므로 두 모양을 똑같이 읽습니다.
이름표 (선택)위쪽 테두리 바깥 왼쪽에 SORICODE 이름표를 테두리에서 1.5칸 띄워 둘 수 있습니다. 데이터는 담지 않습니다. 판독기는 테두리와 떨어진 글자를 무시하고, 한 변에서 바깥으로 튀어나온 부분이 있어도 남은 테두리로 그 변을 찾습니다.
가운데 표시 (선택)짧은 변을 n칸이라 할 때 코드 한가운데 세로 2×round(9n/100)칸, 가로는 그 2배인 자리는 데이터를 넣지 않고 비워 두어 SORI CODE 표시를 그립니다. 형식 정보의 한 비트가 이 자리를 비웠는지 알려 줍니다.
데이터안쪽 (가로−4)×(세로−4)칸에 왼쪽 위부터 한 줄씩, 가운데 표시 자리는 건너뛰며 채웁니다. 한 칸이 1비트이고 검정이 1입니다.

부호화

백색화16비트 LFSR(x16+x14+x13+x11+1, 초깃값 0xACE1) 수열과 XOR 해서 검정과 흰색을 고르게 섞습니다.
형식 정보판 번호, 훼손 대비 수준, 가운데 표시 유무, 가로와 세로 칸 수를 담은 9바이트(6바이트는 패리티)를 맨 앞과 맨 뒤에 한 번씩 둡니다. 정사각형만 되던 이전 판(8바이트)의 코드도 판독기가 읽습니다.
오류 정정GF(256) 리드-솔로몬 부호(원시다항식 0x11D)를 블록당 255바이트 이하로 나누어 쓰고 블록끼리 번갈아 배치합니다. 패리티 비율은 12.5%, 25%, 37.5%입니다.
내용방식 1바이트(0은 UTF-8, 1은 DEFLATE 압축), 언어 2바이트(ISO 639-1), 길이 3바이트, 본문, CRC-32 순서입니다.

크기별 담는 양 (훼손 대비 보통, 가운데 표시 없음, 한글 압축 전)
